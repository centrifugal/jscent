# v1.0.0

A rewrite to the [Centrifugo server SDK specification](https://github.com/centrifugal/gocent/blob/master/spec.md),
version 0.3, for Centrifugo v6. Migrating from jscent 0.2: see [MIGRATING.md](MIGRATING.md).

- No dependencies: `fetch` and Web Crypto only, on Node.js 22 or newer, Deno, Bun and edge runtimes. TypeScript types included; an ES module, which Node.js 22.12+ also loads with `require`.
- Requests and results are generated from Centrifugo's `api.proto`, with its documentation: every API method, including the map and shared poll methods and those of Centrifugo PRO, on the client, a batch and `command` alike - `client.publish({ channel, data })`. A field jscent does not know is refused, not dropped. Promises, not callbacks.
- One deadline per call, over the whole request: `requestTimeout` bounds every call, a call's `timeout` replaces it - longer or shorter - and its `signal` only ends it sooner, never later, so a call made with a long-lived request handler's signal still gives up on a stuck Centrifugo. `broadcastWithRetry`'s `attemptTimeout` is each attempt's own timeout, the call's `timeout` and `signal` still ending it sooner. Redirects are not followed. Your own `fetch` for tracing, pools and tests.
- Errors: `ApiError` with a subclass per known code, `HTTPError`, `UnauthorizedError`, `DecodeError`, `InvalidRequestError`, `InvalidConfigError`, `NetworkError`, `TimeoutError`, `ClosedError`; `retryable()`; hints in messages; Centrifugo's transport error mode.
- **Breaking:** a broadcast or batch in which some parts failed rejects with `BroadcastFailedChannelsError` or `BatchFailedCommandsError`, carrying every part's outcome. `broadcastWithRetry` retries only the channels which may still succeed, under one idempotency key.
- Automatic batching of concurrent calls (`autoBatch`), with no timers.
- Payloads: plain values or `rawJSON`, sent as the same JSON value - `bigint` exactly - with NaN, bytes and other values JSON cannot hold refused before sending; `bigIntegers`, as in centrifuge-js, for integers past 2^53 in replies.
- `jscent/token`: connection, subscription and Centrifugo PRO server API tokens with every claim (HS256, RS256, ES256/384/512, EdDSA), JWKS, `ApiTokens`.
- `jscent/endpoints`: the token, shared poll signature and JWKS endpoints client SDKs call; their function throws `ForbiddenError` for a 403, which client SDKs report as their `UnauthorizedError` (renamed from `Unauthorized`, which read like the API client's `UnauthorizedError`, refused credentials). `jscent/proxy`: a handler for every proxy type. Each is a framework-free core, served by `handler.fetch` (Workers, Bun, Deno, Hono, Next.js) and `handler.node` (node:http, Express).
- `command.publish(...)` and the like for Centrifugo's async consumers - `JSON.stringify` gives the payload as an object, `String(cmd)` the exact text; `jscent/sharedpoll` for shared poll signatures, the expiry required: a `Date`, or `token.NEVER`.
- Fields the protos mark required are required properties, and are checked for a value before sending: `''`, `0`, an empty list or an empty object goes out as the field left out, so a call without one - from plain JavaScript too - rejects with `InvalidRequestError` naming its path (`limitStrategy.rateLimit.policies[0].rate is required`) instead of Centrifugo's code 107. A field whose empty value means something - `invalidateUserTokens`'s `user` - is not checked. Unknown keys of options and token claims are refused, with a hint.
- A nested message with nothing set is left out - an empty `limitStrategy`, which Centrifugo refuses, is not sent - but `deviceUpdate`'s `userUpdate`, `timezoneUpdate`, `localeUpdate` and `metaUpdate` are sent whenever set, even empty: an empty one detaches the devices from their user or clears the setting.
- Constants for the string fields with a fixed set of values, generated from the protos' "One of:" sentences under the names the spec pins (`gen/constants_api.txt`, `gen/constants_proxy.txt`): `PROVIDER_FCM`, `PLATFORM_IOS`, `OP_ADD`, `STATUS_DELIVERED`, `KEY_MODE_IF_NEW`, `CMP_EQ`, `FILTER_NODE_OP_AND`; in `jscent/proxy`, `ENCODING_BINARY`, `PROTOCOL_JSON`, `ALLOW_SUB`, `CAPABILITY_MATCH_WILDCARD`, `CHANNEL_EVENT_TYPE_OCCUPIED`, `FILTER_NODE_OP_AND` and the rest. The fields stay strings.
- `historyAll`, `deviceListAll`, `deviceTopicListAll`, `userTopicListAll` and `mapReadStateAll`: every item of a paged method as an async iterator, a page read when the loop reaches it; `historyAll` yields each publication with its `position`, and `mapReadStateAll` each entry with `state`, the position of the state, reading later pages at the first one's revision. `position` on every result holding an offset and an epoch - of `publish`, `history`, `mapPublish`, `mapRemove`, `mapReadState` and `mapReadStream`: the `since` of the next history call.
- The `profile` claim of connection tokens (Centrifugo PRO). `JSON.stringify` renders results with Centrifugo's field names, errors in them as `{code, message}`; `result.failed` is a getter. A payload's JSON `null` stays `null`.
- TLS certificate errors are not retryable. Any `fetch` fits the option without a cast. `Pending.resolved` and the public constructors of results and partial-failure errors make test doubles.

**Before releasing:** `proto/api.proto` and `proto/proxy.proto` are from Centrifugo's `master` (centrifugal/centrifugo#1308, #1309, #1310), for the "One of:" sentences spec 0.3 generates constants from and `ConnectResult.profile`: sync them again from the first Centrifugo tag holding them (`CENTRIFUGO_REF=vX.Y.Z npm run sync-proto`).
